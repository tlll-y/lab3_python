# Лабораторная работа №3. Каталог объектов

## Медиатека на Python

## О проекте

Для этой лабораторной  сделан каталог медиаматериалов. В него можно добавлять фильмы, музыку и другие записи, искать их по названию или категории, получать по ID и удалять.

Каталог хранится в памяти во время работы программы, но его можно записать в JSON-файл и затем восстановить. Для демонстрации есть отдельная точка входа: при запуске создаётся один фильм, сохраняется каталог и проверяется его загрузка.

## Что нужно для запуска

Нужен **Python 3.12+**. Сам каталог работает без сторонних библиотек. Дополнительные пакеты нужны только для тестов и проверки кода.

| Инструмент | Для чего нужен |
| --- | --- |
| `pytest` | Проверка работы программы через тесты |
| `ruff` | Поиск ошибок в коде и проверка форматирования |
| `mypy` | Проверка аннотаций типов |
| `pre-commit` | Автоматический запуск проверок при коммите |

В программе используются стандартные модули `dataclasses` и `json`. Настройки проекта находятся в `pyproject.toml`.

## Что умеет программа

1. Создание медиаматериала с полями `item_id`, `name`, `category`, `year`, `creator`, `duration_minutes`.
2. Проверку типов и значений полей при создании объекта.
3. Добавление записи с уникальным ID.
4. Получение и удаление записи по ID.
5. Поиск по категории с учётом регистра и точного совпадения.
6. Поиск по части названия без учёта регистра.
7. Получение количества записей и проверку наличия ID.
8. Перебор медиаматериалов в порядке добавления.
9. Сохранение каталога в JSON и загрузку из файла.
10. Обработку ошибок в данных и проверку версии JSON.

## Как устроена работа каталога

### Создание медиаматериала

За одну запись отвечает класс `MediaItem` из `media_item.py`. У него шесть полей:

| Поле | Тип | Содержание |
| --- | --- | --- |
| `item_id` | `str` | Уникальный ID |
| `name` | `str` | Название |
| `category` | `str` | Тип материала, например `фильм` |
| `year` | `int` | Год выпуска |
| `creator` | `str` | Автор или создатель |
| `duration_minutes` | `int` | Продолжительность в минутах |

После создания `MediaItem` автоматически запускается `__post_init__()`. Он проверяет тип каждого поля, непустые строки и положительные значения года и длительности. Если что-то указано неправильно, объект не создаётся — возникает `InvalidMediaItemError`.

Для модели используется `@dataclass(frozen=True)`. Это избавляет от необходимости вручную писать конструктор и не позволяет случайно поменять поля уже созданного объекта обычным присваиванием.

### Добавление, поиск и удаление

Класс `MediaCatalog` хранит записи в словаре `self._items`. Ключом служит `item_id`, значением — сам `MediaItem`.

| Метод | Результат |
| --- | --- |
| `add(item)` | Добавляет запись, предварительно проверив ID |
| `get(item_id)` | Возвращает запись с нужным ID |
| `remove(item_id)` | Удаляет запись |
| `find_by_category(category)` | Возвращает записи с точно совпадающей категорией |
| `find_by_name(search)` | Находит названия, содержащие введённый текст |
| `__len__()` | Позволяет использовать `len(catalog)` |
| `__contains__(item_id)` | Позволяет писать `"001" in catalog` |
| `__iter__()` | Позволяет перебирать записи через `for` |

Для поиска по названию используется `casefold()`: например, запрос `"ПОТТ"` найдёт «Гарри Поттер». Поиск по категории, наоборот, чувствителен к регистру: `"фильм"` и `"Фильм"` считаются разными значениями.

Поскольку внутри используется словарь, обращение к известному ID не требует перебора всех записей. При обычной итерации сохраняется порядок добавления. Методы поиска собирают новый список результатов, не отдавая внутренний словарь каталога.

### Работа с JSON

Для сохранения вызывается `catalog.save("catalog.json")`. Метод преобразует объекты в словари через `asdict()` и записывает их с помощью `json.dump()`. Русский текст остаётся читаемым благодаря `ensure_ascii=False`.

Файл выглядит примерно так:

```json
{
    "format_version": 1,
    "items": [
        {
            "item_id": "001",
            "name": "Гарри Поттер",
            "category": "фильм",
            "year": 2001,
            "creator": "Крис Коламбус",
            "duration_minutes": 152
        }
    ]
}
```

При `load()` программа сначала считывает JSON и проверяет его структуру: корневой объект, версию формата, список `items` и поля каждой записи. Из каждого словаря создаётся `MediaItem`, поэтому проверка данных выполняется ещё раз. Повторяющиеся ID внутри файла тоже запрещены.

Новые объекты сначала помещаются во временный словарь `new_items`. Только когда **весь** файл обработан без ошибок, выполняется `self._items = new_items`. Если загрузка оборвалась на неправильной записи, старый каталог остаётся как был. Это и есть атомарность загрузки в данной работе.

Версия JSON сейчас равна `1`, её значение задано константой `FORMAT_VERSION` в `constants.py`


## Обработка ошибок

Все собственные исключения наследуются от `CatalogError` и находятся в `errors.py`.

| Исключение | Причина |
| --- | --- |
| `InvalidMediaItemError` | Неправильные поля при создании `MediaItem` |
| `DuplicateIDError` | В каталоге уже есть такой ID |
| `ItemNotFoundError` | ID не найден при получении или удалении |
| `UnsupportedFormatVersionError` | Версия JSON отличается от поддерживаемой |
| `CorruptedCatalogError` | JSON имеет неверную структуру, неправильные записи или повторяющиеся ID |

При загрузке ошибки создания `MediaItem` переводятся в `CorruptedCatalogError`. Конструкция `raise ... from err` позволяет сохранить первоначальную причину.

Отсутствующий файл — отдельный случай: сейчас `open()` выдаёт стандартное исключение `FileNotFoundError`, оно не заменяется собственным.

## Пример использования

```python
from src.mediateka.media_catalog import MediaCatalog
from src.mediateka.media_item import MediaItem

catalog = MediaCatalog()
film = MediaItem("001", "Гарри Поттер", "фильм", 2001, "Крис Коламбус", 152)

catalog.add(film)
print(catalog.get("001").name)          # Гарри Поттер
print(catalog.find_by_name("ПОТТ"))    # Список с найденным фильмом
print("001" in catalog)               # True
print(len(catalog))                   # 1

catalog.save("catalog.json")
new_catalog = MediaCatalog()
new_catalog.load("catalog.json")
```

Это пример работы с классами. При обычном запуске пакета из `main.py` выполняется более короткий демонстрационный сценарий.

## Тесты и проверка кода

В проекте **21 тест**: 4 для `MediaItem` и 17 для `MediaCatalog`. Проверяются корректные и неправильные данные, неизменяемость объекта, операции каталога, поиск, сохранение, загрузка и ошибки JSON. Отдельный тест проверяет, что неудачная загрузка не изменяет существующий каталог.

Для проверки ожидаемых ошибок в тестах используется `pytest.raises()`. При работе с JSON применяется `tmp_path`, чтобы создавать временные файлы и не трогать данные проекта.

Запуск тестов:

```bash
python -m pytest -v
```

Проверки Ruff и mypy:

```bash
python -m ruff check src
python -m ruff format --check src
python -m mypy src 
```

Если нужно подключить проверки к коммитам, из корня Git-репозитория выполняется:

```bash
pre-commit install
pre-commit run --all-files
```
