
# Лабораторная работа №3. Каталог объектов

## Результат

Реализован пакет `src.mediateka` для хранения и управления каталогом медиаматериалов.

Программа позволяет добавлять, находить и удалять объекты, выполнять поиск по категории и названию, сохранять каталог в JSON и восстанавливать его из файла.

Предметная область — медиатека.

## Возможности

- Добавление медиаматериалов с уникальными ID.
- Получение и удаление объектов по ID.
- Поиск по категории.
- Поиск по части названия без учёта регистра.
- Получение количества объектов через `len()`.
- Проверка наличия ID через `in`.
- Перебор объектов в порядке добавления.
- Сохранение и загрузка JSON.
- Проверка корректности данных.
- Защита каталога от частичного изменения при ошибке загрузки.
- Обработка ошибок с помощью собственных исключений.

## Модель медиаматериала

Класс `MediaItem` реализован с помощью `dataclass`.

Поля:

| Поле | Тип | Описание |
|---|---|---|
| `item_id` | `str` | Уникальный идентификатор |
| `name` | `str` | Название |
| `category` | `str` | Категория |
| `year` | `int` | Год выпуска |
| `creator` | `str` | Автор или создатель |
| `duration_minutes` | `int` | Длительность в минутах |

При создании проверяются типы и допустимость значений полей.

Строковые поля не должны быть пустыми или состоять только из пробелов. Год и длительность должны быть положительными целыми числами.

Объект `MediaItem` является неизменяемым благодаря `frozen=True`.

## Методы каталога

| Метод | Назначение |
|---|---|
| `add(item)` | Добавление объекта |
| `get(item_id)` | Получение объекта по ID |
| `remove(item_id)` | Удаление по ID |
| `find_by_category(category)` | Поиск по категории |
| `find_by_name(search)` | Поиск по части названия |
| `__len__()` | Количество объектов |
| `__contains__(item_id)` | Проверка наличия ID |
| `__iter__()` | Перебор объектов |
| `save(file_path)` | Сохранение в JSON |
| `load(file_path)` | Загрузка из JSON |

### Особенности реализации

Объекты хранятся во внутреннем словаре, где ключ — строковый ID, а значение — `MediaItem`.

Поиск по ID выполняется через словарь.

Повторное добавление объекта с уже существующим ID запрещено.

Поиск по названию выполняется по подстроке без учёта регистра с помощью `casefold()`.

Поиск по категории использует точное сравнение названия категории.

Порядок итерации соответствует порядку добавления объектов. При удалении и повторном добавлении объект оказывается в конце.

Методы поиска возвращают новые списки, а не внутреннюю изменяемую коллекцию каталога.

## Сохранение в JSON

Каталог сохраняется в JSON-файл с полями `format_version` и `items`.

Пример структуры:

```json
{
    "format_version": 1,
    "items": [
        {
            "item_id": "001",
            "name": "Гарри Поттер",
            "category": "фильм",
            "year": 2001,
            "creator": "Крис Коламбус",
            "duration_minutes": 152
        }
    ]
}
```

Для преобразования `MediaItem` в словарь используется `asdict()`.

Для сохранения применяется `json.dump()`, для загрузки — `json.load()`.

Текущая версия формата — `1`. Номер версии изменяется при изменении структуры сохраняемых JSON-данных.

### Атомарность загрузки

Загружаемые медиаматериалы сначала создаются и проверяются во временном словаре.

Если хотя бы один объект некорректен, загрузка прекращается и существующий каталог не изменяется.

Только после успешной проверки всех объектов временный словарь заменяет содержимое каталога.

## Исключения

Все предметные исключения наследуются от `CatalogError`.

| Исключение | Причина |
|---|---|
| `InvalidMediaItemError` | Некорректные поля медиаматериала |
| `DuplicateIDError` | Повторяющийся ID при добавлении |
| `ItemNotFoundError` | Объект с указанным ID отсутствует |
| `UnsupportedFormatVersionError` | Неподдерживаемая версия JSON |
| `CorruptedCatalogError` | Неправильная структура или данные JSON |

## Тестирование

Запустить все тесты:

```bash
python -m pytest -v
```

Тесты проверяют создание корректных и некорректных объектов, добавление, получение, удаление, дубликаты ID, поиск, порядок итерации, сохранение и загрузку JSON.

Также проверяются повреждённые данные, неизвестная версия формата и сохранение старого состояния каталога при неудачной загрузке.
